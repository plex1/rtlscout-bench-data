# Design Summary — `tpu` (weight-stationary 8×8 MXU)

**Final best: `design14.v` — PASS, cost 2,226,857** (vs. starting point 4,624,409, a 2.08× improvement). Area 4588, delay 485 ps (slack −5.7 ps).

## 1. Approaches tried (in order)

| File | Idea | Cost | Result |
|---|---|---|---|
| starting_point.v | Original logikbench RTL | 4.62M | PASS |
| design1.v | Internal accumulator 32→19 bits (max \|Σ·a·b\| = 8·128·128 = 2^17 needs exactly 19 signed bits), sign-extend only at output | 3.24M | PASS |
| design2.v | Carry-save (redundant) psum chain: raw partial-product rows + 13-CSA tree; CPA only once per column after de-skew | 2.83M | PASS |
| design3.v | + radix-4 Booth (5 CSAs, 4 levels) | 2.62M | PASS |
| design5.v | + unshifted carry vector (18 stored bits, bit 0 structurally 0), binary de-skew, reset only on valid pipe | 2.50M | PASS |
| design8/10/13.v | Booth digit decode hoisted out of the 64 PEs — 12-bit control chains (sel/neg/two), decode at array input before skew | 2.31M | PASS |
| design14.v | + exact ±w registered at load time → **no correction-bit rows**, 4 CSAs / 3 levels | **2.23M** | PASS |

## 2. Highest-impact optimizations
1. **Narrowing the accumulator 32→19 bits** (pure math insight; −30% cost, zero risk).
2. **Carry-save psum chains** — removing the 19-bit CPA from every PE was the single biggest structural win; conversion happens once per column.
3. **Radix-4 Booth on the activation with decode hoisted to the array input**: product rows depend on the activation only through 12 control bits (sel/neg/two per digit), so 8 decoders replace 64 and the decode leaves the PE critical path.
4. **Registering exact ±w at load** — Booth's "+1" correction rows vanish, shrinking the CSA tree from 7 rows/4 levels to 6 rows/3 levels (both area and delay).

## 3. What failed / regressed
- **IW=18** is arithmetically impossible: max positive sum +131072 = 2^17 needs 19 signed bits.
- **Booth-on-weight (design7)**: pre-decoding w is legal but control chains interact badly with mid-stream reloads and row-broadcast variants violate the exact τ(i,j)=i+j injection schedule the golden trace enforces (mid-drain weight reload vectors catch any deviation).
- **Row-broadcast capture scheme (design11/15)**: replacing de-skew chains with capture registers failed on multi-tile/back-to-back streams (values stale by one row) — the de-skew chain in design14 is the correct cycle-accurate structure. Never fully recovered the alignment proof.
- Recurring Verilog pitfalls that cost debugging turns: 1-bit shift operands losing bits, `wire` declarations inside procedural loops, `D==0` empty array ranges, and mis-placed carry-shift in a hand-built CSA tree.

## 4. Lessons learned
- The golden trace's *stall + reload semantics* pin the per-PE schedule exactly (τ=i+j); only optimizations preserving it are viable. Verify schedule-equivalence before building.
- Narrow datapaths to the provable dynamic range first — cheapest large win.
- In systolic arrays, attack the repeating cell's critical path (redundant arithmetic, fewer compression levels) rather than I/O plumbing, which is already minimal.
- When hand-crafting CSA trees, double-check every carry input is shifted and every row count is complete — one wrong wire produces distinctive "÷8" or all-ones symptoms that pinpoint the bug.
- Next time: try `target_delay` sweeps only after RTL structure is settled; structure dominated every result here (300/500/850 ps targets were nearly inert).
