# Summary

## 1. Outcome
Best passing design: **`starting_point.v`** (modified in place), correctness PASS on all 1,999,992 checks, **area_delay_product ≈ 8.107e+05** — down from the unmodified baseline of **9.68e+05** (≈16% better). Several candidate rewrites in `design.sv` were abandoned.

## 2. What worked (ranked by impact)
All changes were made to `starting_point.v` as small, individually-evaluated edits:

1. **3:2-only balanced reduction tree (`red32`)** replacing `csa_tree` for the 17-operand compression. The original `compressor_4to2` uses 5:3 counters with ~4-XOR logic depth; a pure full-adder tree is shallower. Biggest single delay win (~823 ps path).
2. **Mask + end-correction negation.** Replaced per-lane two's complement (`~x+1`) with `x ^ {sign}` plus a single `corr = popcount(signs)` added once to the final sum. Removes 17 negation adders and a whole adder level from stage 2.
3. **Cheap unsigned max tree (`max_tree`/`max2u`)** replacing `comp_tree`'s sign-magnitude comparator. Enabled by biasing all exponents by `2**(EW-1)` so the entire compare/difference path is unsigned.
4. **Registering the multiplier product** (`sum+carry` folded into a single register) instead of two buses — halved those pipeline-2 flops.
5. **Folding the acc-lane product** into the same operand vector and using `pipe1_rg_exp_acc` directly in the max tree instead of a duplicated `rg_exp_items` bus.

## 3. What didn't work / regressions
- **`design.sv`**: a full rewrite (5-value 7-bit exponents, `final_mant = {sum_norm[18:8], |sum_norm[7:0]}` — note the original truly uses `[18:8]`, not `[18:12]`). It persistently failed with `exp=8038 got=8039` (off-by-one in the exponent) from zero/sign-extended part-select assignments to wider signed signals. I never found the root cause and reverted to editing the baseline.
- **Splitting the max tree across stages 0/1** (4-lane group maxima pre-registered): ADP got *worse* (1.01e6) — the extra registered buses cost more than the depth saved.
- **Truncated 5×5 multiplier**: rejected — `MANT_WIDTH_I = 3`, so the mantissas are only 4 bits (one guard bit), and applying `>> (MUL_WIDTH-ALIGN_WIDTH)` directly to the truncated product is **not** equivalent to truncating the 4×4 product first.
- **`target_delay = 1000`**: raised area slightly and delay a lot; the ADP-optimal point stayed at 500 ps.

## 4. Lessons learned
- **Edit the known-good baseline incrementally.** The baseline PASSes out of the box; here the highest returns came from surgical module substitutions, not from rewriting the top level.
- **`run_evaluation` gives a full critical-path report** — use it every time to pick the next target rather than guessing.
- **Watch for sign-extension semantics** when assigning a narrow signed expression to a wider signed vector; this is the likely root cause of the `design.sv` off-by-one and it cost many steps.
- **The 500 ps target is already the ADP sweet spot** here; don't sweep `target_delay` first, restructure RTL first.

### Next steps if continuing
Stage 3 (CSA tree + final 20-bit add) and the input `posit_decoder` (16×2 instances of LZC + barrel shifter) are now the likely critical paths. The decoder is duplicated `N` times per input vector and is a strong candidate for sharing/simplifying; the exponent adder tree in stage 1 also still has ~4 levels above the multiplier.
