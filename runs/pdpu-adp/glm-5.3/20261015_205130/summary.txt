# Design Session Summary

## Final Result
**PASS** with cost **9.68e+05** (area_delay_product) — achieved by the provided `starting_point.v` (baseline). My rewrite (`v1.sv`) remained incomplete at the step limit.

## 1. Approaches tried

- **Evaluated the baseline** (`starting_point.v`): PASS, area 1063, delay 910 ps, ADP 968,045, worst path = pipe2→pipe3 (exponent-max → aligner → negate path, 23 levels of logic).
- **Ground-up rewrite** (`v1.sv`) targeting both area and delay:
  - Replaced booth-radix-4 Wallace multipliers with plain 4×4 `*` multipliers.
  - Replaced LZC prefix networks with priority-select loops.
  - Replaced recursive comp/CSA trees with flat balanced trees.
  - Replaced cascaded 5:3-counter 4:2 compressors with XOR/AND carry-save stages.
  - Kept upstream pipeline cut points (5-cycle latency) and port interface.

## 2. What worked / progressed

Getting `v1.sv` to compile under Yosys+Verilator required several fixes (no `automatic` block locals for Yosys, no duplicate identifiers, valid `always_comb`). Correctness steadily improved as bugs were found and fixed:
- LZC returned MSB *index* instead of leading-zero *count* (fixed: `cnt = 18 - b`).
- acc decoder must decode only the 15 magnitude bits (`p[14:0]`), not all 16.
- `notzero` (implicit-bit) must be pipelined into stage 5 (appended to `fmn`).
- Encoder mantissa field must exclude the implicit bit (`sum_norm[17:6]`, not `[18:6]`).
- `k` must be *sign*-extended before shifting (`{{2{k[3]}}, k}`), not zero-extended.
- Found and modeled the upstream **quirky comparator**: for same-sign (both negative) inputs it compares magnitudes, so it returns the *most-negative* value — not a true signed max.
- Found missing alignment shift on the accumulator term.
- Found CSA pass-through bug (`s4[3] = {s3[4],1'b0} + s3[5]` doubled a term).

With those fixes, the **entire uniform-lane sweep (65,536 vectors) passed** — decode, multiply, exponent max, accumulate, normalize, and encode were all verified correct for that subspace.

## 3. What didn't work / regressions

- **The per-lane corner sweep never passed.** The persistent residue `exp=0x21X got=0x1fX` (got ≈ 15/16 of expected, ratio 16/17) indicated a systematic scale/sticky error for corner operands — likely in the alignment shift-amount semantics (`|diff[6:5] ? 14 : diff[4:0]`) where I flip-flopped between `dif ≥ 8 → 0`, `dif ≥ 14 → 0`, and bit-placement variants without isolating the true cause.
- I burned several steps reverting/re-applying the same clamp fix instead of first isolating which *single* term (product vs acc, left vs right shift) was wrong.
- Time lost to a mis-structured `create_file` (encoder written twice in one file) — one full rewrite step.

## 4. Lessons learned

1. **Instrument early.** A tiny standalone testbench (I drafted `tbx.sv` but never got to run it) dumping my stage-1/2 intermediates for one failing vector would have localized the alignment bug in one step instead of ~10.
2. **Never edit two interacting unknowns at once.** The alignment clamp and the CSA pass-through bug masked each other; the "same" clamp fix failed twice because of the unrelated CSA error.
3. **Read the reference model before re-deriving semantics.** The oracle (`tb.sv` `pdpu_top__ref`) is the ground truth, including its width-truncation quirks (`op[15:14]` → `op[14:13]`, zero-extension of the 11-bit mantissa into a 12-bit port, the magnitude-comparing negative comparator).
4. **Establish a verified-correct baseline early, then optimize incrementally** rather than rewriting the whole datapath in one shot — the baseline passed and my rewrite did not catch up within 60 steps.
5. Yosys front-end constraints (no `automatic` locals in `always_comb`, no packed-2D slicing) should be respected from the first line of code.
