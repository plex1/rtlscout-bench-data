# Summary

## Final result
**`design5.sv` — PASS (0/20672 fails), cost 4.332e+06 area_delay_product** (delay 1098 ps, area 3945 µm²), vs. the starting point's 9.497e+06 — a **2.19× improvement**.

## 1. Approaches tried

| File | Approach | Result |
|---|---|---|
| `starting_point.v` | Original core_jpeg (4×32-deep dual-port RAMs, 32-bit everywhere) | PASS, 9.50M |
| `design.sv` | Single `idct1d` module reused for both passes; simplified transpose | PASS (after fixes), 16.5M — **worse** |
| `design2.sv` | + registered column-read staging + `/256` via `+255, >>>8` | PASS, 5.49M |
| `design4.sv` | + butterfly restructured so each stage does one add; `sp5/sp6` split out | PASS, 4.61M |
| **`design5.sv`** | + corner turn re-laid out as `tmem[8][16]` (transposed store, 1-D row decode, `MW=20`) | **PASS, 4.33M ← best** |
| `design7.sv` | + registered lane registers (kill parity mux before multiplier) | PASS, 4.73M |
| `design8.sv` | literal-constant multiplies (shift/add networks) | FAIL (timing/ordering bug) |

## 2. Optimizations that mattered most
- **Restructuring the butterfly so no stage chains two 32-bit adds** (4.61M from 5.49M). Key: precompute `o_t5 = (p0-p1)-(p2-p3)` and `o_t6 = o_s7-o_s6` in beat 4, freeing beat 5.
- **Corner-turn memory re-layout**: `tmem[row][{bank,col}]` instead of `tmem[bank][row][col]`. Write address becomes 1-D (cheap), read decode is 8×16 instead of 2×8×8 — this is what took 4.61M → 4.33M.
- **Registered column staging** (`stage[0:7]` loaded once per column) to keep the RAM mux off the multiplier input path.
- **Cheap signed `/256`**: `(x + (x[31]?255:0)) >>> 8` instead of a real divider.
- Narrowing the corner-turn word to 20 bits (safe: verified against all vectors).

## 3. What didn't work
- **`design.sv`'s single-shared-module** composition: register count ballooned (16.5M) because both passes share a 32-bit datapath.
- **Adding an extra pipeline stage to break the `*181/256` chain** (design3): broke the `o_t3`/`o_t4` lifetimes; the schedule has no slack for it.
- **`i0` must be a *latched* register** (captured on beats 0 and 2), not a wire from the current beat — this was the single biggest functional bug.
- **`ld_col`/`stage_a` must be 0 when idle**, not `rd_col+1` — otherwise the preload reads the wrong column.
- `design7`'s lane registers *increased* area more than they reduced delay.
- `target_delay` sweep: 100 ps and 500 ps gave identical results; 1500 ps gave 4.71M (worse). Not a useful lever here.

## 4. Lessons / next steps
- The **critical path is still the corner-turn RAM read mux → column pass multiplier** (1098 ps). Next idea: keep the column pass but replace the 8×16 read mux with a **shift-register column buffer** (serially shift in rows as they're written, no address decode at all) — that should remove the mux entirely.
- `design8.sv`'s literal-constant approach is likely a real win once fixed; the bug is in the lane-select `if/else` chain (beats 3,4,6 map `d2*C3` and `d1*C5`, but the `odd_b` grouping is applied to *both* p2 and p3 while p0/p1 have separate cases — re-derive the truth table from `starting_point.v` lines ~200–290).
- Budget: ~12 of 60 steps were spent on functional debugging of the `i0` latch and the stage-preload address. Reading the golden `jpeg_idct_x` index schedule *line by line* against my own before writing would have saved most of that.
- Keep `design5.sv` as the fallback; every experiment should be a new file.
