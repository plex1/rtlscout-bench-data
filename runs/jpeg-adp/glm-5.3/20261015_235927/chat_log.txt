## Specification
Full 8x8 2-D IDCT of a baseline JPEG decoder (ultraembedded/core_jpeg), module
name `jpeg_idct_2d`: the row pass (jpeg_idct_x, OUT_SHIFT=11), a double-buffered
corner-turn (jpeg_idct_transpose with four 32x32 dual-port RAMs), and the column
pass (jpeg_idct_y, OUT_SHIFT=15), composed exactly as in the original decoder
(downstream ready tied high; the row pass accepts no backpressure). Each 1-D
pass is the factorized (AAN-style) algorithm with cosine constants scaled by
4096 (C1..C7 = 4017, 3784, 3406, 2896, 2276, 1567, 799), time-sharing 5
multipliers over an 8-beat schedule. ALL arithmetic is evaluated in 32-bit
signed context with wrap-around; outputs of each pass are arithmetic-shifted
right (11 then 15); the 1/sqrt(2) odd-part scaling is `(x * 181) / 256` where
`*` wraps at 32 bits and `/` is SIGNED division truncating toward zero. This
exact fixed-point behavior is what the golden vectors encode.

Interface (clocked, sync active-high reset `rst`; no backpressure):
  inputs : clk, rst, img_start_i (1-cycle pulse resets the output streamers),
           img_end_i (unused), inport_valid_i, inport_idx_i[2:0],
           inport_data0..3_i[15:0]
  outputs: outport_valid_o, outport_data_o[31:0], outport_idx_o[5:0]

Input protocol (the upstream block serializer's FIXED schedule, reproduced
exactly by the testbench): per row of 8 coefficients c0..c7 (16-bit signed),
8 back-to-back valid beats with idx = 0..7; the four data lanes carry the EVEN
set (c0,c2,c4,c6) on beats idx in {0,2,5,7} and the ODD set (c1,c3,c5,c7) on
beats idx in {1,3,4,6}. 8 rows back-to-back form a 64-beat block; between
blocks there are >= 2 idle cycles (valid=0, idx=0, data=0). Pipeline registers
advance every clock regardless of valid — designs must be robust to the gap
pattern exactly as the original is.

Output (fixed schedule): 64 values per block streamed on outport_valid_o; the
k-th streamed value of a block carries outport_idx_o = {k[2:0], k[5:3]} (the
column pass emits column-major; the idx label gives the ROW-MAJOR pixel
position) and must match the expected output at that position. The stream of a
block overlaps the next block's input beats (the transpose double-buffers one
full block).

A working starting point is provided: `starting_point.v` contains the
ORIGINAL core_jpeg modules (Apache 2.0), unmodified, under a thin composition
top. It passes all golden vectors (they were generated from it — the original
RTL is the correctness oracle). Study it, then optimize while preserving its
exact behavior. Sibling benchmark: `jpeg_idct_2d_spire` (identical tb.sv +
vectors.dat, bit-exact SpireHDL starting point). The 1-D row pass alone is
also available as the `jpeg_idct_x_*` benchmarks.

NOTE on memories: the cost-evaluation synthesis flow targets a standard-cell
library with no RAM macros, so every behavioral memory in this design (the
transpose buffers, block_out, etc.) is inferred as a register array plus mux
decode REGARDLESS of coding style. Optimizing that decode/mux logic is fair
game; instantiating a hard RAM macro is not possible in this flow.

## Delay Optimization Tips
- `target_delay` trades area against delay (a lower value pressures toward faster logic, a higher value lets Yosys re-map to smaller cells). Do not overly iterate on different target delays; often the RTL structure is the real lever, target_delay is only a minor secondary knob.
- After getting a correct design, try different accumulation orderings (sequential vs. tree) and compare results — Yosys synthesis can produce noticeably different delays (~10 ps) from structurally similar descriptions.
- For designs dominated by a multiply-accumulate chain, the critical path is the multiplier followed by the adder tree. Reducing the adder depth or splitting into parallel partial sums can help.

### Parallel-prefix adder (ripple-carry / carry-lookahead) (Add.sv)
```systemverilog
// Copyright 2024 ETH Zurich and University of Bologna.
// Solderpad Hardware License, Version 0.51, see LICENSE for details.
// SPDX-License-Identifier: SHL-0.51
//
// Based on the work by Reto Zimmermann 1998 - ETH Zürich
// Originally written in VHDL, available under: 
// https://iis-people.ee.ethz.ch/~zimmi/arith_lib.html#library
//
// Authors:
// - Thomas Benz <tbenz@iis.ee.ethz.ch>
// - Philippe Sauter <phsauter@iis.ee.ethz.ch>
// - Paul Scheffler <paulsc@iis.ee.ethz.ch>
//
// Description :
// Binary adder using ripple-carry or parallel-prefix carry-lookahead logic.
// S = A+B

module Add #(
	parameter int              width = 8,             // word width
	parameter lau_pkg::speed_e speed = lau_pkg::FAST  // performance parameter
) (
	input  logic [width-1:0] A,  // operands
	input  logic [width-1:0] B,
	output logic [width-1:0] S   // sum
);

	// Function: Binary adder using parallel-prefix carry-lookahead logic.

	logic [width-1:0] GI, PI;  // prefix gen./prop. in
	logic [width-1:0] GO, PO;  // prefix gen./prop. out
	logic [width-1:0] PT;  // adder propagate temp

	// Internal signals for unsigned operands
	logic [width-1:0] Auns, Buns, Suns;

	// default ripple-carry adder as slow implementation
	if (speed == lau_pkg::SLOW) begin
		// type conversion: std_logic_vector -> unsigned
		assign Auns = A;
		assign Buns = B;

		// addition
		assign Suns = Auns + Buns;

		// type conversion: unsigned -> std_logic_vector
		assign S = Suns;
	end else begin
		// parallel-prefix adders as medium and fast implementations

		// calculate prefix input generate/propagate signals
		assign GI = A & B;
		assign PI = A | B;
		// calculate adder propagate signals (PT = A xor B)
		assign PT = ~GI & PI;

		// calculate prefix output generate/propagate signals
		PrefixAndOr #(
			.width(width),
			.speed(speed)
		) prefix (
			.GI(GI),
			.PI(PI),
			.GO(GO),
			.PO(PO)
		);

		// calculate sum bits
		assign S = PT ^ {GO[width-2:0], 1'b0};
	end
endmodule



module behavioural_Add #(
	parameter int              width = 8,             // word width
	parameter lau_pkg::speed_e speed = lau_pkg::FAST  // performance parameter
) (
	input  logic [width-1:0] A,  // operands
	input  logic [width-1:0] B,
	output logic [width-1:0] S   // sum
);
	assign S = A + B;
endmodule
```

### Prefix AND-OR structures (Sklansky, Brent-Kung, serial) (PrefixAndOr.sv)
```systemverilog
// Copyright 2024 ETH Zurich and University of Bologna.
// Solderpad Hardware License, Version 0.51, see LICENSE for details.
// SPDX-License-Identifier: SHL-0.51
//
// Based on the work by Reto Zimmermann 1998 - ETH Zürich
// Originally written in VHDL, available under: 
// https://iis-people.ee.ethz.ch/~zimmi/arith_lib.html#library
//
// Authors:
// - Thomas Benz <tbenz@iis.ee.ethz.ch>
// - Philippe Sauter <phsauter@iis.ee.ethz.ch>
// - Paul Scheffler <paulsc@iis.ee.ethz.ch>
//
// Description :
// Prefix structures of different depth (i.e. speed) for carry calculation
// in binary adders. Compute in m levels new generate/propagate signal pairs
// for always larger groups of bits. Generate signals of the last level correspond
// to carries in binary addition. Basic logic operations: AND-OR for generate
// signals, AND for propagate signals.

module PrefixAndOr #(
	parameter int              width = 8,             // word width
	parameter lau_pkg::speed_e speed = lau_pkg::FAST  // performance parameter
) (
	input  logic [width-1:0] GI,  // gen./prop. in
	input  logic [width-1:0] PI,  // gen./prop. in
	output logic [width-1:0] GO,  // gen./prop. out
	output logic [width-1:0] PO   // gen./prop. out
);

	// Constants
	localparam int n = width;  // prefix structure width
	localparam int m = $clog2(width);  // prefix structure depth

	// Sklansky parallel-prefix carry-lookahead structure
	if (speed == lau_pkg::FAST) begin : fastPrefix
		logic [(m+1)*n-1:0] GT, PT;  // gen./prop. temp
			assign GT[n-1:0] = GI;
			assign PT[n-1:0] = PI;
			for (genvar l = 1; l <= m; l++) begin : levels
				for (genvar k = 0; k < 2 ** (m - l); k++) begin : groups
					for (genvar i = 0; i < 2 ** (l - 1); i++) begin : bits
						// pass prop and gen to following nodes
						if ((k * 2 ** l + i) < n) begin : white
							assign GT[l*n+k*2**l+i] = GT[(l-1)*n+k*2**l+i];
							assign PT[l*n+k*2**l+i] = PT[(l-1)*n+k*2**l+i];
						end
						// calculate new propagate and generate
						if ((k * 2 ** l + 2 ** (l - 1) + i) < n) begin : black
							assign GT[l*n + k*2**l + 2**(l-1) + i] = 
												GT[(l-1)*n + k*2**l + 2**(l-1) + i]
											  | (  PT[(l-1)*n + k*2**l + 2**(l-1) + i]
												 & GT[(l-1)*n + k*2**l + 2**(l-1) - 1] );
							assign PT[l*n + k*2**l + 2**(l-1) + i] = 
													PT[(l-1)*n + k*2**l + 2**(l-1) + i]
												  & PT[(l-1)*n + k*2**l + 2**(l-1) - 1];
						end
					end
				end
			end
			assign GO = GT[(m+1)*n-1 : m*n];
			assign PO = PT[(m+1)*n-1 : m*n];
	end

	// Brent-Kung parallel-prefix carry-lookahead structure
	if (speed == lau_pkg::MEDIUM) begin : mediumPrefix
		logic [(2*m)*n -1:0] GT, PT;  // gen./prop. temp
		assign GT[n-1:0] = GI;
		assign PT[n-1:0] = PI;

		for (genvar l = 1; l <= m; l++) begin : levels1
			for (genvar k = 0; k < 2**(m-l); k++) begin : groups
				for (genvar i = 0; i < 2**l -1; i++) begin : bits
					if ((k* 2**l +i) < n) begin : white
						assign GT[l*n + k* 2**l +i] = GT[(l-1)*n + k* 2**l +i];
						assign PT[l*n + k* 2**l +i] = PT[(l-1)*n + k* 2**l +i];
					end // white
				end // bits
				if ((k* 2**l + 2**l -1) < n) begin : black
					assign GT[l*n + k* 2**l + 2**l -1] =
								GT[(l-1)*n + k* 2**l + 2**l - 1] |
							  | (  PT[(l-1)*n + k* 2**l + 2**l     -1] 
							     & GT[(l-1)*n + k* 2**l + 2**(l-1) -1]);
					assign PT[l*n + k* 2**l + 2**l -1] =
								PT[(l-1)*n + k*2**l + 2**l     -1] 
							  & PT[(l-1)*n + k*2**l + 2**(l-1) -1];
				end // black
			end
		end // level1
		for (genvar l = m +1; l < 2*m; l++) begin : levels2
			for (genvar i = 0; i < 2**(2*m -l); i++) begin : bits
				if (i < n) begin : white
					assign GT[l*n +i] = GT[(l-1)*n +i];
					assign PT[l*n +i] = PT[(l-1)*n +i];
				end // white
			end // bits
			for (genvar k = 1; k < 2**(l-m); k++) begin : groups
				if (l < 2*m -1) begin : empty
					for (genvar i = 0; i < 2**(2*m -l -1) -1; i++) begin : bits
						if ((k* 2**(2*m -l) +i) < n) begin : white
							assign GT[l*n + k* 2**(2*m -l) +i] = GT[(l-1)*n + k* 2**(2*m -l) +i];
							assign PT[l*n + k* 2**(2*m -l) +i] = PT[(l-1)*n + k* 2**(2*m -l) +i];
						end // white
					end
				end // empty
				if ((k* 2**(2*m -l) + 2**(2*m -l -1) -1) < n) begin : black
					assign GT[l*n + k* 2**(2*m -l) + 2**(2*m -l-1) -1] = 
								GT[(l-1)*n + k* 2**(2*m-l) + 2**(2*m -l-1) -1]
							  | (  PT[(l-1)*n + k* 2**(2*m-l) + 2**(2*m-l-1) -1] 
								 & GT[(l-1)*n + k* 2**(2*m-l) -1] );
					assign PT[l*n + k* 2**(2*m -l) + 2**(2*m -l-1) -1] = 
								PT[(l-1)*n + k* 2**(2*m -l) + 2**(2*m -l-1) -1]
							  & PT[(l-1)*n + k* 2**(2*m -l) -1];
				end // black
				for (genvar i = 2**(2*m -l-1); i < 2**(2*m -l); i++) begin : bits
					if ((k* 2**(2*m -l) +i) < n) begin : white
						assign GT[l*n + k* 2**(2*m -l) +i] = GT[(l-1)*n + k* 2**(2*m -l) +i];
						assign PT[l*n + k* 2**(2*m -l) +i] = PT[(l-1)*n + k* 2**(2*m -l) +i];
					end // white
				end
			end
		end // level2
		assign GO = GT[2*m*n -1 : (2*m -1) * n];
		assign PO = PT[2*m*n -1 : (2*m -1) * n];
	end  // Serial-prefix carry-lookahead structure
	else if (speed == lau_pkg::SLOW) begin : slowPrefix
		logic [n-1:0] GT, PT;  // gen./prop. temp
		assign GT[0] = GI[0];
		assign PT[0] = PI[0];
		
		for (genvar i = 1; i < n; i++) begin : bits
			assign GT[i] = GI[i] | (PI[i] & GT[i-1]);
			assign PT[i] = PI[i] & PT[i-1];
		end
		assign GO = GT;
		assign PO = PT;
	end

endmodule

```

// Self-checking testbench for jpeg_idct_2d — the full 8x8 2-D IDCT
// (x-pass -> transpose -> y-pass) of ultraembedded/core_jpeg.
// Reads vectors.dat: one line per 8x8 block = 64 input coefficients (16-bit
// signed, 4 hex digits, row-major c[row][col]) followed by 64 expected outputs
// (32-bit, 8 hex digits, in ROW-MAJOR pixel order — outputs are matched via
// outport_idx_o, which labels each streamed value with its row-major position).
//
// Drive protocol: identical to the jpeg_idct_x benchmark (the upstream block
// serializer's fixed schedule): per row 8 back-to-back valid beats idx=0..7,
// EVEN coefficient set (c0,c2,c4,c6) at idx in {0,2,5,7}, ODD set (c1,c3,c5,c7)
// at idx in {1,3,4,6}; 8 rows back-to-back per 64-beat block; >= 2 idle cycles
// between blocks (valid=0, idx=0, data=0).
//
// Output contract (fixed schedule): 64 values per block streamed on
// outport_valid_o; the k-th value of a block carries
// outport_idx_o == {k[2:0], k[5:3]} (the y-pass un-transpose permutation) and
// must equal the expected output at that row-major position. Comparison is
// EXACT (integer outputs).
module tb;
  int total_checks;
  int total_errors;

## Summary

**Final result: PASS, cost 6.10M area_delay_product** (starting point: 9.49M → **36% reduction**).

### Files
- `design5.v` — best design (PASS, 6,103,917)
- `design2.v` — earlier passing variant (9.19M), RAM-based transpose
- `design.v` — first correct variant (9.25M), near-verbatim structure
- `design3.v` — 8-bank mux transpose, correct but slow (15.15M)

### What I did
1. **Baseline restructure** (`design.v`): kept the original structure but merged each 1-D pass's `jpeg_idct_x`/`jpeg_idct_y` into one parameterized `idct1d` module, replaced the 64-entry `ptr_conv` ROM in the y-pass with `{cnt[2:0], cnt[5:3]}` bit-swap, and replaced `/256` signed division with shift+round-toward-zero correction. Only marginal gain (9.25M) — the critical path was the transpose RAM's 32:1 read mux.

2. **Narrowed datapaths** (`design2.v`): reduced multiplier operand registers (constants 13-bit), shrank transpose RAMs to 32×21, shrank y-pass output regs. Small gain (9.19M) — area dropped but delay rose.

3. **Shift-register transpose** (`design5.v`, the big win): replaced the 4 RAMs + 16-word read-address adder/decoder with 128 individual 20-bit registers addressed `set*64 + row*8 + col`. Write decode is one 6-bit term per cell; read is **always the head (col 0) of each row bank**, with a 2:1 lane mux (`idx[0]^idx[2]`) picking even/odd row pairs. The storage shifts once per 8-beat group. This removed the entire read-mux critical path (2160 ps → 1497 ps) with *equal* total register count.

4. **Narrowed the ×181 multiplier** (last edit, being evaluated when time ran out): sliced the wrap-only-needed `t65*181` product to `e[31:8]` plus round correction. Final state not yet evaluated.

### What failed / regressions
- **8-bank mux transpose** (`design3.v`): read path was 16:1 mux + lane mux; Yosys mapped it to 3660 ps (worst of all). Address-mux-based reads are poison in this flow.
- **Datapath width guessing**: truncating `t65` to 21 bits and y-outputs to 16 bits broke correctness (13496 errors) — the `×181` intermediate needs ~30-31 bits. Fixed by slicing from the exact 32-bit-wrap semantics instead of guessing ranges.
- Several pipeline-delay bugs (valid/index misalignment, missing `block_out_tmp` two-cycle transfer for `bo[7]`) — each cost an evaluation round.

### Lessons
- The behavioral-memory read mux, not the arithmetic, was the dominant delay; converting a RAM into a "shift-out column" register file eliminated it entirely at zero area cost.
- Preserve exact bit-level semantics (32-bit wrap, truncating division) by *deriving* widths from the 32-bit wrap mask rather than from range analysis.
- Budget carefully: I spent ~20 of 60 steps on pipeline-debugging cycles that a careful delay-table on paper would have avoided, leaving no time to evaluate the final narrowed-multiplier variant (which should shave more delay from the now-critical ×181 path).
