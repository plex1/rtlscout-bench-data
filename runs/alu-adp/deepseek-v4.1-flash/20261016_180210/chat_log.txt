side by side with the upstream ALU on the same stimulus. At every falling clock
edge after reset, ready_o must equal the upstream ALU's ready_o; whenever the
upstream ALU is ready, result_o must equal its result, and comparison_result_o

Vector (SIMD) lanes: vector_mode_i partitions the 32-bit datapath into one 32-bit,
two 16-bit, or four 8-bit independent lanes (2'b01 is never driven). "Per lane"
below means the operation is applied independently in each lane of a and b.

Semantics by group ("s" = two's-complement signed, "u" = unsigned):

* Adder family (per lane): SUB/SUBU/SUBR/SUBUR compute a-b, the others a+b.
  The lane results are then post-processed on the concatenated 32-bit value:
    1. A rounding constant is added (plain 32-bit add, carries may cross lanes):
       for ADDR/SUBR/ADDUR/SUBUR the constant is bmask>>1 where
       bmask = (~(32'hFFFFFFFE << bmask_a_i)) << bmask_b_i
       (a run of bmask_a_i+1 ones starting at bit bmask_b_i); for
       ADD/SUB/ADDU/SUBU the constant is 0.
    2. The sum is right-shifted per lane: arithmetically for ADD/SUB/ADDR/SUBR,
       logically for the U variants. The per-lane shift amount is normally
       bmask_b_i (truncated to the lane's amount width: 5/4/3 bits for
       32/16/8-bit lanes); when is_clpx_i=1 it is clpx_shift_i instead.
  With bmask_a_i=bmask_b_i=0 (the common case) this is a plain per-lane add/sub.
  is_subrot_i=1 (only ever driven with SUB, two 16-bit lanes): before the
  subtraction the operands' halves are cross-swapped: the effective operands are
  {b[15:0], a[31:16]} minus {a[15:0], b[31:16]} (per-lane 16-bit subtraction) —
  i.e. result high half = b_lo - a_lo, low half = a_hi - b_hi.

* Logic: AND = a&b, OR = a|b, XOR = a^b (lane-independent).

* Shifts (per lane): SLL logical left, SRL logical right, SRA arithmetic right.
  Per-lane shift amounts come from the corresponding lane of operand_b_i,
  truncated to 5/4/3 bits for 32/16/8-bit lanes (e.g. in 32-bit mode: b[4:0];
  in 16-bit mode: lane 0 uses b[3:0], lane 1 uses b[19:16]).
  ROR in 32-bit mode rotates a right by b[4:0]. (In 16/8-bit vector modes ROR
  is driven but degenerates to a per-lane logical right shift, matching the
  shared shifter datapath.)

* Vector comparisons (per lane): LTS/LTU a<b, LES/LEU a<=b, GTS/GTU a>b,
  GES/GEU a>=b (S = signed, U = unsigned), EQ a==b, NE a!=b.
  result_o: each lane is filled with all-ones if the lane comparison is true,
  else all-zeros. comparison_result_o = the result of the most-significant lane
  (the whole-word result in 32-bit mode).
  Scalar set-less (32-bit only): SLTS/SLTU (a<b), SLETS/SLETU (a<=b);
  result_o = {31'b0, flag} and comparison_result_o = flag.
  comparison_result_o is only checked for these 14 comparison opcodes; for every
  other opcode it is a don't-care.

* MIN/MINU/MAX/MAXU (per lane): minimum / maximum of a and b (signed for
  MIN/MAX, unsigned for MINU/MAXU).

* ABS (per lane; operand_b_i is always 0 for ABS): |a| (two's-complement
  negation of negative lanes; the most negative value wraps to itself).
  With is_clpx_i=1 (driven only in 16-bit mode): complex conjugate —
  result = {-a[31:16], a[15:0]}.

* CLIP/CLIPU (32-bit only, any operand_b_i value; in practice b = 2^k - 1):
  Let lo = ~b (i.e. -(b+1)) and hi = b, as signed values.
    CLIP:  if a <s lo or a == lo -> lo; else if a >s hi -> hi (signed min of
           a and b); else a. I.e. clamp(a, ~b, b) for b >= 0.
    CLIPU: if a <=s 0 -> 0; else signed-min(a, b).

* Extract/insert (16/8-bit vector modes only; operand_c_i is always 0 for
  EXT/EXTS): sel = imm_vec_ext_i (2 bits in 8-bit mode, only bit 0 in 16-bit
  mode).
    EXT:  zero-extend lane sel of a to 32 bits.
    EXTS: sign-extend lane sel of a to 32 bits.
    INS:  result = operand_c_i with lane sel replaced by the low lane of a
          (a[7:0] in 8-bit mode, a[15:0] in 16-bit mode).

* Shuffle/pack (16/8-bit vector modes only). Notation: x.B[i] = byte i of x,
  x.H[i] = 16-bit half i of x.
    SHUF  8-bit:  result.B[k] = a.B[ b.B[k][1:0] ]           for k=3..0
    SHUF  16-bit: result.H[k] = a.H[ b.H[k][0] ]             for k=1..0
    SHUF2 8-bit:  result.B[k] = (b.B[k][2] ? a : c).B[ b.B[k][1:0] ]
    SHUF2 16-bit: result.H[k] = (b.H[k][1] ? a : c).H[ b.H[k][0] ]
    PCKLO 16-bit: {a[15:0],  b[15:0]}
    PCKHI 16-bit: {a[31:16], b[31:16]}
    PCKLO 8-bit:  {c[31:16], a[7:0], b[7:0]}
    PCKHI 8-bit:  {a[7:0], b[7:0], c[15:0]}

* Bit-manipulation (32-bit mode only). Define
  bmask = (~(32'hFFFFFFFE << bmask_a_i)) << bmask_b_i (a run of bmask_a_i+1
  ones starting at bit bmask_b_i, truncated at bit 31).
    BCLR:  a & ~bmask
    BSET:  a | bmask
    BEXTU: (a >> b[4:0]) & bmask                      (logical shift)
    BEXT:  t = a >>> b[4:0] (arithmetic shift);
           result = (t & bmask) | ({32{t[bmask_a_i]}} & ~bmask)
           (extract then sign-extend from bit bmask_a_i)
    BINS:  ((a << b[4:0]) & bmask) | (c & ~bmask)
    BREV:  t = a << b[4:0]; then reverse t in groups selected by bmask_a_i[1:0]:
           0: single bits (full 32-bit bit-reversal of t)
           1: 2-bit groups: result[2j+1:2j] = t[31-2j : 30-2j] for j=0..15
           2: 3-bit groups: result[3j+2:3j] = t[31-3j : 29-3j] for j=0..9,
              result[31:30] = 0
           3: same as 0
  (In practice b[4:0] equals bmask_b_i for BEXT/BEXTU/BINS, but arbitrary
  combinations are driven and must match the formulas above.)

* Bit-count (32-bit mode only, result on 6 bits zero-extended to 32):
    CNT: number of set bits in a
    FF1: index of the least-significant set bit of a, or 32 if a==0
    FL1: index of the most-significant set bit of a, or 32 if a==0
    CLB: count of leading bits of a equal to the sign bit a[31], minus one
         (i.e. redundant sign bits); special case a==0 -> 0. Examples:
         a=32'hFFFFFFFF -> 31, a=32'h00000001 -> 30, a=32'h40000000 -> 0.

* Serial divider (32-bit mode only). NOTE the operand roles: the DIVIDEND is
  operand_b_i and the DIVISOR is operand_a_i. RISC-V M-extension semantics:
    DIVU: b /u a;  a==0 -> 32'hFFFFFFFF
    DIV:  b /s a (quotient rounds toward zero);  a==0 -> 32'hFFFFFFFF;
          b==0x80000000, a==0xFFFFFFFF -> 0x80000000
    REMU: b %u a;  a==0 -> b
    REM:  b %s a (sign follows the dividend);  a==0 -> b;
          b==0x80000000, a==0xFFFFFFFF -> 0
  These four ops go through the serial divider and take several cycles; the
  cycle count must be exactly the starting point's (see the contract above).

Driven input envelope (anything outside is a don't-care, testbench never drives
it): only the 57 opcodes above; vector_mode_i in {00,10,11} and restricted to
32-bit mode for logic*, bit-manip, bit-count, scalar set-less, clip and div/rem
(*logic ops are lane-independent anyway); bmask_a_i/bmask_b_i are nonzero only
for the adder family and bit-manip ops; imm_vec_ext_i nonzero only for
EXT/EXTS/INS; is_clpx_i only for ABS (16-bit mode) and the adder family;
is_subrot_i only for SUB (16-bit mode); clpx_shift_i nonzero only when
is_clpx_i=1; ABS sees operand_b_i==0 only; EXT/EXTS see operand_c_i==0 only.

Everything outside the driven envelope is a don't-care and is never exercised.

## Delay Optimization Tips
- `target_delay` trades area against delay (a lower value pressures toward faster logic, a higher value lets Yosys re-map to smaller cells). Do not overly iterate on different target delays; often the RTL structure is the real lever, target_delay is only a minor secondary knob.
- After getting a correct design, try different accumulation orderings (sequential vs. tree) and compare results — Yosys synthesis can produce noticeably different delays (~10 ps) from structurally similar descriptions.
- For designs dominated by a multiply-accumulate chain, the critical path is the multiplier followed by the adder tree. Reducing the adder depth or splitting into parallel partial sums can help.

### Parallel-prefix adder (ripple-carry / carry-lookahead) (Add.sv)
```systemverilog
// Copyright 2024 ETH Zurich and University of Bologna.
// Solderpad Hardware License, Version 0.51, see LICENSE for details.
// SPDX-License-Identifier: SHL-0.51
//
// Based on the work by Reto Zimmermann 1998 - ETH Zürich
// Originally written in VHDL, available under: 
// https://iis-people.ee.ethz.ch/~zimmi/arith_lib.html#library
//
// Authors:
// - Thomas Benz <tbenz@iis.ee.ethz.ch>
// - Philippe Sauter <phsauter@iis.ee.ethz.ch>
// - Paul Scheffler <paulsc@iis.ee.ethz.ch>
//
// Description :
// Binary adder using ripple-carry or parallel-prefix carry-lookahead logic.
// S = A+B

module Add #(
	parameter int              width = 8,             // word width
	parameter lau_pkg::speed_e speed = lau_pkg::FAST  // performance parameter
) (
	input  logic [width-1:0] A,  // operands
	input  logic [width-1:0] B,
	output logic [width-1:0] S   // sum
);

	// Function: Binary adder using parallel-prefix carry-lookahead logic.

	logic [width-1:0] GI, PI;  // prefix gen./prop. in
	logic [width-1:0] GO, PO;  // prefix gen./prop. out
	logic [width-1:0] PT;  // adder propagate temp

	// Internal signals for unsigned operands
	logic [width-1:0] Auns, Buns, Suns;

	// default ripple-carry adder as slow implementation
	if (speed == lau_pkg::SLOW) begin
		// type conversion: std_logic_vector -> unsigned
		assign Auns = A;
		assign Buns = B;

		// addition
		assign Suns = Auns + Buns;

		// type conversion: unsigned -> std_logic_vector
		assign S = Suns;
	end else begin
		// parallel-prefix adders as medium and fast implementations

		// calculate prefix input generate/propagate signals
		assign GI = A & B;
		assign PI = A | B;
		// calculate adder propagate signals (PT = A xor B)
		assign PT = ~GI & PI;

		// calculate prefix output generate/propagate signals
		PrefixAndOr #(
			.width(width),
			.speed(speed)
		) prefix (
			.GI(GI),
			.PI(PI),
			.GO(GO),
			.PO(PO)
		);

		// calculate sum bits
		assign S = PT ^ {GO[width-2:0], 1'b0};
	end
endmodule



module behavioural_Add #(
	parameter int              width = 8,             // word width
	parameter lau_pkg::speed_e speed = lau_pkg::FAST  // performance parameter
) (
	input  logic [width-1:0] A,  // operands
	input  logic [width-1:0] B,
	output logic [width-1:0] S   // sum
);
	assign S = A + B;
endmodule
```

### Prefix AND-OR structures (Sklansky, Brent-Kung, serial) (PrefixAndOr.sv)
```systemverilog
// Copyright 2024 ETH Zurich and University of Bologna.
// Solderpad Hardware License, Version 0.51, see LICENSE for details.
// SPDX-License-Identifier: SHL-0.51
//
// Based on the work by Reto Zimmermann 1998 - ETH Zürich
// Originally written in VHDL, available under: 
// https://iis-people.ee.ethz.ch/~zimmi/arith_lib.html#library
//
// Authors:
// - Thomas Benz <tbenz@iis.ee.ethz.ch>
// - Philippe Sauter <phsauter@iis.ee.ethz.ch>
// - Paul Scheffler <paulsc@iis.ee.ethz.ch>
//
// Description :
// Prefix structures of different depth (i.e. speed) for carry calculation
// in binary adders. Compute in m levels new generate/propagate signal pairs
// for always larger groups of bits. Generate signals of the last level correspond
// to carries in binary addition. Basic logic operations: AND-OR for generate
// signals, AND for propagate signals.

module PrefixAndOr #(
	parameter int              width = 8,             // word width
	parameter lau_pkg::speed_e speed = lau_pkg::FAST  // performance parameter
) (
	input  logic [width-1:0] GI,  // gen./prop. in
	input  logic [width-1:0] PI,  // gen./prop. in
	output logic [width-1:0] GO,  // gen./prop. out
	output logic [width-1:0] PO   // gen./prop. out
);

	// Constants
	localparam int n = width;  // prefix structure width
	localparam int m = $clog2(width);  // prefix structure depth

	// Sklansky parallel-prefix carry-lookahead structure
	if (speed == lau_pkg::FAST) begin : fastPrefix
		logic [(m+1)*n-1:0] GT, PT;  // gen./prop. temp
			assign GT[n-1:0] = GI;
			assign PT[n-1:0] = PI;
			for (genvar l = 1; l <= m; l++) begin : levels
				for (genvar k = 0; k < 2 ** (m - l); k++) begin : groups
					for (genvar i = 0; i < 2 ** (l - 1); i++) begin : bits
						// pass prop and gen to following nodes
						if ((k * 2 ** l + i) < n) begin : white
							assign GT[l*n+k*2**l+i] = GT[(l-1)*n+k*2**l+i];
							assign PT[l*n+k*2**l+i] = PT[(l-1)*n+k*2**l+i];
						end
						// calculate new propagate and generate
						if ((k * 2 ** l + 2 ** (l - 1) + i) < n) begin : black
							assign GT[l*n + k*2**l + 2**(l-1) + i] = 
												GT[(l-1)*n + k*2**l + 2**(l-1) + i]
											  | (  PT[(l-1)*n + k*2**l + 2**(l-1) + i]
												 & GT[(l-1)*n + k*2**l + 2**(l-1) - 1] );
							assign PT[l*n + k*2**l + 2**(l-1) + i] = 
													PT[(l-1)*n + k*2**l + 2**(l-1) + i]
												  & PT[(l-1)*n + k*2**l + 2**(l-1) - 1];
						end
					end
				end
			end
			assign GO = GT[(m+1)*n-1 : m*n];
			assign PO = PT[(m+1)*n-1 : m*n];
	end

	// Brent-Kung parallel-prefix carry-lookahead structure
	if (speed == lau_pkg::MEDIUM) begin : mediumPrefix
		logic [(2*m)*n -1:0] GT, PT;  // gen./prop. temp
		assign GT[n-1:0] = GI;
		assign PT[n-1:0] = PI;

		for (genvar l = 1; l <= m; l++) begin : levels1
			for (genvar k = 0; k < 2**(m-l); k++) begin : groups
				for (genvar i = 0; i < 2**l -1; i++) begin : bits
					if ((k* 2**l +i) < n) begin : white
						assign GT[l*n + k* 2**l +i] = GT[(l-1)*n + k* 2**l +i];
						assign PT[l*n + k* 2**l +i] = PT[(l-1)*n + k* 2**l +i];
					end // white
				end // bits
				if ((k* 2**l + 2**l -1) < n) begin : black
					assign GT[l*n + k* 2**l + 2**l -1] =
								GT[(l-1)*n + k* 2**l + 2**l - 1] |

					assign PT[l*n + k* 2**l + 2**l -1] =
								PT[(l-1)*n + k*2**l + 2**l     -1] 
							  & PT[(l-1)*n + k*2**l + 2**(l-1) -1];
				end // black
			end
		end // level1
		for (genvar l = m +1; l < 2*m; l++) begin : levels2
			for (genvar i = 0; i < 2**(2*m -l); i++) begin : bits
				if (i < n) begin : white
					assign GT[l*n +i] = GT[(l-1)*n +i];
					assign PT[l*n +i] = PT[(l-1)*n +i];
				end // white
			end // bits
			for (genvar k = 1; k < 2**(l-m); k++) begin : groups
				if (l < 2*m -1) begin : empty
					for (genvar i = 0; i < 2**(2*m -l -1) -1; i++) begin : bits
						if ((k* 2**(2*m -l) +i) < n) begin : white
							assign GT[l*n + k* 2**(2*m -l) +i] = GT[(l-1)*n + k* 2**(2*m -l) +i];
							assign PT[l*n + k* 2**(2*m -l) +i] = PT[(l-1)*n + k* 2**(2*m -l) +i];
						end // white
					end
				end // empty
				if ((k* 2**(2*m -l) + 2**(2*m -l -1) -1) < n) begin : black
					assign GT[l*n + k* 2**(2*m -l) + 2**(2*m -l-1) -1] = 
								GT[(l-1)*n + k* 2**(2*m-l) + 2**(2*m -l-1) -1]
							  | (  PT[(l-1)*n + k* 2**(2*m-l) + 2**(2*m-l-1) -1] 
								 & GT[(l-1)*n + k* 2**(2*m-l) -1] );
					assign PT[l*n + k* 2**(2*m -l) + 2**(2*m -l-1) -1] = 
								PT[(l-1)*n + k* 2**(2*m -l) + 2**(2*m -l-1) -1]
							  & PT[(l-1)*n + k* 2**(2*m -l) -1];
				end // black
				for (genvar i = 2**(2*m -l-1); i < 2**(2*m -l); i++) begin : bits
					if ((k* 2**(2*m -l) +i) < n) begin : white
						assign GT[l*n + k* 2**(2*m -l) +i] = GT[(l-1)*n + k* 2**(2*m -l) +i];
						assign PT[l*n + k* 2**(2*m -l) +i] = PT[(l-1)*n + k* 2**(2*m -l) +i];
					end // white
				end
			end
		end // level2
		assign GO = GT[2*m*n -1 : (2*m -1) * n];
		assign PO = PT[2*m*n -1 : (2*m -1) * n];
	end  // Serial-prefix carry-lookahead structure
	else if (speed == lau_pkg::SLOW) begin : slowPrefix
		logic [n-1:0] GT, PT;  // gen./prop. temp
		assign GT[0] = GI[0];
		assign PT[0] = PI[0];
		
		for (genvar i = 1; i < n; i++) begin : bits
			assign GT[i] = GI[i] | (PI[i] & GT[i-1]);
			assign PT[i] = PI[i] & PT[i-1];
		end
		assign GO = GT;
		assign PO = PT;
	end

endmodule
```

module cv32e40p_popcnt (
    input  logic [31:0] in_i,
    output logic [ 5:0] result_o
);

  logic [15:0][1:0] cnt_l1;
  logic [ 7:0][2:0] cnt_l2;
  logic [ 3:0][3:0] cnt_l3;
  logic [ 1:0][4:0] cnt_l4;

  genvar l, m, n, p;
  generate
    for (l = 0; l < 16; l++) begin : gen_cnt_l1
      assign cnt_l1[l] = {1'b0, in_i[2*l]} + {1'b0, in_i[2*l+1]};
    end
  endgenerate

  generate
    for (m = 0; m < 8; m++) begin : gen_cnt_l2
      assign cnt_l2[m] = {1'b0, cnt_l1[2*m]} + {1'b0, cnt_l1[2*m+1]};
    end
  endgenerate

  generate
    for (n = 0; n < 4; n++) begin : gen_cnt_l3
      assign cnt_l3[n] = {1'b0, cnt_l2[2*n]} + {1'b0, cnt_l2[2*n+1]};
    end
  endgenerate

  generate
    for (p = 0; p < 2; p++) begin : gen_cnt_l4
      assign cnt_l4[p] = {1'b0, cnt_l3[2*p]} + {1'b0, cnt_l3[2*p+1]};
    end
  endgenerate

  assign result_o = {1'b0, cnt_l4[0]} + {1'b0, cnt_l4[1]};

module cv32e40p_ff_one #(
    parameter LEN = 32
) (
    input logic [LEN-1:0] in_i,

    output logic [$clog2(LEN)-1:0] first_one_o,
    output logic                   no_ones_o
);

  localparam NUM_LEVELS = $clog2(LEN);

  logic [          LEN-1:0][NUM_LEVELS-1:0] index_lut;
  logic [2**NUM_LEVELS-1:0]                 sel_nodes;
  logic [2**NUM_LEVELS-1:0][NUM_LEVELS-1:0] index_nodes;


  //////////////////////////////////////////////////////////////////////////////
  // generate tree structure
  //////////////////////////////////////////////////////////////////////////////

  generate
    genvar j;
    for (j = 0; j < LEN; j++) begin : gen_index_lut
      assign index_lut[j] = $unsigned(j);
    end
  endgenerate

  generate
    genvar k;
    genvar l;
    genvar level;

    assign sel_nodes[2**NUM_LEVELS-1] = 1'b0;

    for (level = 0; level < NUM_LEVELS; level++) begin : gen_tree
      //------------------------------------------------------------
      if (level < NUM_LEVELS - 1) begin : gen_non_root_level
        for (l = 0; l < 2 ** level; l++) begin : gen_node
          assign sel_nodes[2**level-1+l]   = sel_nodes[2**(level+1)-1+l*2] | sel_nodes[2**(level+1)-1+l*2+1];
          assign index_nodes[2**level-1+l] = (sel_nodes[2**(level+1)-1+l*2] == 1'b1) ?
                                           index_nodes[2**(level+1)-1+l*2] : index_nodes[2**(level+1)-1+l*2+1];
        end
      end
      //------------------------------------------------------------
      if (level == NUM_LEVELS - 1) begin : gen_root_level
        for (k = 0; k < 2 ** level; k++) begin : gen_node
          // if two successive indices are still in the vector...
          if (k * 2 < LEN - 1) begin : gen_two
            assign sel_nodes[2**level-1+k] = in_i[k*2] | in_i[k*2+1];
            assign index_nodes[2**level-1+k] = (in_i[k*2] == 1'b1) ? index_lut[k*2] : index_lut[k*2+1];
          end
          // if only the first index is still in the vector...
          if (k * 2 == LEN - 1) begin : gen_one
            assign sel_nodes[2**level-1+k]   = in_i[k*2];
            assign index_nodes[2**level-1+k] = index_lut[k*2];
          end
          // if index is out of range
          if (k * 2 > LEN - 1) begin : gen_out_of_range
            assign sel_nodes[2**level-1+k]   = 1'b0;
            assign index_nodes[2**level-1+k] = '0;
          end
        end
      end
      //------------------------------------------------------------
    end
  endgenerate

  //////////////////////////////////////////////////////////////////////////////
  // connect output
  //////////////////////////////////////////////////////////////////////////////

  assign first_one_o = index_nodes[0];
  assign no_ones_o   = ~sel_nodes[0];

endmodule

## Summary

**Final result:** `design.sv` passes 100% of the equivalence checks (0/1,028,192 fails) with `area_delay_product = 592,919` (area 443 µm², delay 1338 ps), a **~8% improvement** over the `starting_point.sv` baseline (645,629 / 442 / 1462 ps).

### 1. Approaches tried

I started by reading the whole 1452-line `starting_point.sv` plus the reference model embedded in `tb.sv` (second half) to pin down exact semantics. My strategy was:

- **Baseline check first** — evaluated `starting_point.sv` unmodified to get the reference cost (645,629). Also confirmed `target_delay` (100 vs 500) has essentially *zero* effect on this design; Yosys maps it identically. So `target_delay` is not a useful knob here.
- **Full clean re-implementation** in `design.sv`: same datapath structure (adder / shifter / comparator / shuffle / bitop / divider) but with variable names, muxing, and result selection restructured.

### 2. What had the most impact

- **Flattened result mux** — replaced the big `unique case (operator_i)` with a one-hot masked-OR tree. This alone took delay from 1462 → 1338 ps.
- Keeping all datapaths faithful while cleaning up the control/decode logic. The critical path runs opcode-decode → shifter → result mux, so decode restructuring pays off at both ends.
- Removing the 64-bit ROR datapath in favor of a 32-bit rotate (`>>amt | <<(32-amt)`, exploiting 5-bit wrap) — theoretically the biggest remaining lever; see below.

### 3. What didn't work / caused regressions

- **Three semantic traps** in the upstream RTL that are *not* in the prose spec and will silently break equivalence:
  1. `adder_result_expanded = $signed(adder_in_a) + $signed(adder_in_b)` on 36-bit operands producing 37 bits — the sign bit `[36]` is the **sign-extended** MSB (i.e. the whole-32-bit-lane add carry), not a plain carry-out. Needed for CLIP's underflow test. I initially wrote `{1'b0, a} + {1'b0, b}` and broke CLIP.
  2. `clb_result = ff1_result - 5'd1` relies on **context-width extension**: the 6-bit LHS makes this a 6-bit subtract, so `ff1_result==0` yields `6'h3F`, not `31`. My explicit `{1'b0, ...}` broke CLB.
  3. In 16/8-bit modes, shift amounts are taken as `shift_amt_int[19:16]` / `[3:0]` (which contain the *upper* lane's amount), not a clean per-lane selector — the "correct-looking" fix broke the byte-lane fixed shifts.
- **My final in-flight edit** (32-bit rotate + fill-select shifter) was still incorrect when the step limit hit — the byte-lane `[26:24]/[18:16]/[10:8]/[2:0]` selectors must be preserved verbatim, and I had also mangled them. `design.sv` currently holds that broken variant, so **the next agent should revert the shifter block in `design.sv` to the 64-bit `shift_op_a_32` version** (which is the state that produced the 592,919 PASS) before doing anything else.

### 4. Lessons learned

- **Trust the RTL, not the prose.** Every failure I hit came from "cleaning up" an upstream quirk that the spec text described imprecisely. When a bit-level expression looks wrong but the reference passes, it is load-bearing.
- **Diff the error message against the line number carefully** — I twice chased phantom "off-by-N" line offsets and wasted steps modifying correct code while the real bug sat elsewhere.
- **Debug by observation, not reasoning.** A one-line temporary hack dumping internal signals into `result_o` immediately localized the CLIP bug after several failed reasoning passes.
- **Budget:** the 65k-token ceiling killed my last two turns mid-edit. I should have stopped optimizing at the verified-PASS state (step 54) and only attempted one small, self-contained change per step, evaluating after each. Larger rewrites late in the run risk ending on a broken file — which is exactly what happened.
- **Next steps worth trying** (on top of the reverted, passing `design.sv`): (a) the 32-bit rotate done correctly, (b) splitting the shifter into narrow per-lane barrel shifters with a `{1'b0, lane}` mask for saturation, (c) `case`-based byte/half/word selection feeding the result mux instead of a pure wire-OR, and (d) factoring the shared `operator_i` decode into one-hot signals computed once and reused by adder/shifter/mux to cut redundant decode depth.
