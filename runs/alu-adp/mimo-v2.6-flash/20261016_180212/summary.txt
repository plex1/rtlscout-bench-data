## Summary

**Final result:** `starting_point.sv` — **568,970** ADP (area 434.15 × delay 1310.54 ps), vs. baseline 645,629 (441.54 × 1462.22) = **−11.9%**, 0/1,028,192 checks failing.

### 1. Approaches tried
- **Baseline calibration:** evaluated `starting_point.sv` directly as the design (tb embeds its own reference), so all work was incremental edits on it. Swept `target_delay` first to see if the knob mattered.
- **Function-shrink via divider surgery:** replaced the divider's 32-bit magnitude comparator with the subtract's own carry-out + a zero-detect (`ABComp = (~|AddOut) | (AddWide[32] ^ CompInv)`).
- **Envelope-aware opcode decoding:** rewrote decodes (`adder_op_b_negate`, `shift_use_round`, `shift_arithmetic`, `special`, `do_min`, `shift_left`, `div_valid`, `is_round`) into shorter SOP forms valid for the 57 driven opcodes only.
- **Dead-opcode case-item folding:** added never-driven opcodes (e.g. `01000xx`, `0111100/101`) as case items so ABC's SOP minimizer collapses whole leaves — *legal* don't-care use.
- **Major adder restructure (PLAN X):** mode32 fused carry-save chain + ≤16-bit vector pack + output mux; CLIP's bit36 re-derived as `(a31&b31)|((a31^b31)&~carry)`.
- **Divider BReg elimination:** reconstructed the divisor register from held inputs + cycle counter.

### 2. What had the most impact
1. **Dead-opcode case-item folding (−5.5%, 601.8k → 569.0k)** — biggest single win; cut 76 ps by shortening the result-mux decode, at zero area cost.
2. **Divider comparator reuse (−6%, 645.6k → 606.6k)** — removed a whole comparator from the netlist.
3. **Decode trim round 1 (−0.8%)** — `negate = op[3]&op[0]|subrot`, `use_round = op[4]&op[3]`, compact `shift_arithmetic`.

### 3. What didn't work (reverted)
- **`target_delay`** — inert (300 ≡ 500 exactly); RTL structure is the only lever.
- **bmask as comparators** — −3.7 area but bmask became the critical-path start (+66 ps).
- **PLAN X (both versions)** — correctness took 2 evals to fix (I had wired the raw carry instead of the derived flag), but the third adder cost +17…23 area, swamping the −59…−64 ps delay gain (623k / 605k).
- **x-literal don't-cares** — synthesized to 579k (−3.7%) but the harness explicitly bans X/Z and casex/casez; the legal case-item form recovers most of it.
- **BReg elimination** — functionally exact, but put ff_one→shifter→adder on the input→AReg path (delay 2153 ps).
- **Later decode trims** (`shift_left`, `div_valid`, `is_round`, `do_min`, `op[6]`→BREV branch) — net regressions; ABC's mapping is sensitive to SOP shape, so simpler-in-text ≠ smaller-after-ABC.

### 4. Lessons
- **Cost = area×delay punishes any hardware bought with delay** — every "fuse the adder" idea died on area; only *function* shrinks (deleted logic) reliably win.
- **ABC flattens structure**: re-writing the same boolean function differently is a no-op; only changing the function (dead opcodes, envelope don't-cares) changes the netlist.
- **Don't lengthen input→register paths** in the sequential divider; reg-to-reg was fine, input-fed logic was fatal.
- **Cost extraction requires a passing sim**, so breakage-based diagnostics are unmeasurable — keep reverts exact (edit old/new strings) and eval each change alone.
- **Enumerate all 57 driven opcodes per decode change** (I did this by hand every time; it caught several false "simplifications").
- Experimenting is cheap: the harness keeps the best *passing* design, so bold attempts only cost steps, never the record.
